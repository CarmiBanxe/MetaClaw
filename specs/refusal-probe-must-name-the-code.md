# Проба отказа обязана называть КОД, а не только класс

> **S0-02 · РЕШЕНИЕ · дисциплина проб**
>
> Исполняет требование «проба обязана измерять названную защиту, а не предшествующий отказ».
>
> Основание: `DECISIONS-OPERATOR-ACCEPTED-2026-09-10.md`; учёт — `REGISTER-OPEN-ITEMS-2026-09-10.md`.


## Цель

Дерево уже ловит **пробу, которая не может упасть**. Здесь — соседний случай: **проба, которая
упасть может, но не различает, ЧТО именно упало.**

```ts
expect(() => acceptManifest(tampered, sha256)).toThrow(OrgRefusal);
```

Класс `OrgRefusal` несёт **тринадцать** разных отказов. Проба зелена при любом из них. Добавьте
завтра новый страж РАНЬШЕ проверяемого — проба останется зелёной, измеряя другой предмет, и
никто об этом не узнает.

## Контекст — что измерено

Замер 2026-09-10 на `b87a9041`, сплошной по всем `*.spec.ts` вне `dist`:

```
утверждений toThrow(<КлассОтказа>)          74
из них БЕЗ кода отказа рядом (±6 строк)     49   ← 66 %
```

**Как это нашлось.** Не поиском дефектов, а собственной ошибкой измерения. Считая долг
непроверенных отказов, я засчитала `toThrow(OrgRefusal)` за проверку
`MANIFEST_SUPERSESSION_WITHOUT_SUCCESSOR`. Ручная сверка показала: та проба проверяет
**подделанный манифест**, то есть `MANIFEST_TAMPERED` — совсем другой отказ. **Одна проба
засчиталась за тринадцать.**

Из-за этого мой замер долга дал вилку шириной сорок (`37 ≤ долг ≤ 77`) вместо числа.

## Область работ

### Входит

- мера, считающая `toThrow(<Класс>)` без кода рядом, с храповиком;
- различение двух случаев: код назван рядом · назван только класс;
- исправление **не всех сорока девяти**, а объявленной первой партии — с канарейкой на каждую.

### Не входит

- запрет `toThrow(<Класс>)` как такового: он законен там, где предмет пробы — **сам класс**
  (например «наружу не уходит посторонний тип исключения»). Такие случаи помечаются явно и
  выводятся из счёта **пометкой в пробе**, а не молчанием меры;
- переписывание проб ради формы: проба, проверяющая отказ **сообщением**, кода не требует —
  сообщение отличает отказ не хуже кода;
- изменение самих отказов и их классов.

## Функциональные требования

- **R1.** Мера считает утверждения вида `toThrow(<Идентификатор, оканчивающийся на Refusal>)` и
  `rejects.toThrow(...)` и делит их на два разряда: **код рядом** и **только класс**.
- **R2.** «Рядом» определяется числом строк, и число **печатается каждым прогоном**. Сегодня ±6;
  всякое иное значение обязано быть названо, потому что оно и есть половина ответа.
- **R3.** Проба, намеренно проверяющая КЛАСС, помечается в самой пробе (`// КЛАСС-ПО-СУЩЕСТВУ:
  <довод>`) и в счёт «только класс» не входит. **Пометка без довода пометкой не является.**
- **R4.** Храповик: число «только класс» не растёт молча; рост — отказ меры с именами новых.
- **R5.** Мера печатает **предел**: она видит форму утверждения, а не его смысл. Проба, где код
  назван рядом, но относится к другому вызову, ею не ловится.
- **R6.** Мера печатает **знаменатель** — сколько классов отказа несёт каждый затронутый класс.
  «Одна проба на тринадцать отказов» и «одна проба на два» — разные величины беды, и одно число
  их смешивает.

## Крайние случаи и ошибки

- **E1.** `toThrow` с регулярным выражением по сообщению → в счёт **не входит**: сообщение
  различает отказ.
- **E2.** `toThrow()` вовсе без довода → **отдельный, худший разряд**: «бросает хоть что-нибудь».
  Считать его вместе с классом значило бы смешать слабое с никаким.
- **E3.** Проба в файле, исключённом из прогона набора, → считается отсутствующей.
- **E4.** Класс, у которого отказ ровно один → «только класс» ему равносилен коду; такие случаи
  печатаются отдельной строкой и в долг не идут.

## Критерии приёмки

- **A1.** Прогон даёт `74 / 49` либо объясняет расхождение с этим замером поимённо.
- **A2.** Разряд E2 (`toThrow()` без довода) посчитан отдельно и напечатан.
- **A3.** Разряд E4 (класс с единственным отказом) посчитан отдельно и **вычтен** из долга.
- **A4.** Канарейка роста: подсадить `toThrow(<Класс>)` без кода → отказ меры, названо ровно оно.
- **A5.** Канарейка пометки: пометить подсадку `// КЛАСС-ПО-СУЩЕСТВУ: <довод>` → счёт падает на
  единицу; пометка **без** довода счёт не меняет.
- **A6.** Первая партия исправлений: не менее пяти проб получают код в утверждении, и **каждая**
  сопровождается канарейкой, показывающей, что прежняя редакция оставалась зелёной при подмене
  отказа на соседний того же класса.
- **A7.** Ни одна существующая проба не ослаблена; число проб каждого затронутого набора до и
  после названо.

## Проверка

Прогон меры до и после; канарейки A4–A5 в изолированном снимке; для A6 — по каждой правке два
прогона: старая редакция при подменённом отказе (зелёная — вот дефект) и новая (красная).

## Определение готовности

Каждый пункт A получил PASS с доказательством; мера зелёная на точном SHA; A6 воспроизведена
независимо центральным терминалом хотя бы на одной пробе.
