# Runbook: P4.3-Q235 — qwen3:235b-a22b RPC split (evo2 master + evo1 worker)

**Sprint anchor:** ADR-018 §"Required sprints to reach 100%" item 2.
**Goal:** Unblock qwen3:235b-a22b inference via llama.cpp RPC tensor split across 2 nodes (combined 192 GiB CPU > 133 GiB model).
**Predecessor:** INS-2026-05-04-P4.3-EVO2 (UMA rebalance DONE) + INS-2026-05-04-P4.3-Q235-DEFER (standalone CPU FAILED).
**Risk:** medium-high — llama.cpp RPC проверен для dense models (glm-master = GLM-4.5-Air 105B dense), MoE 235B+RPC compatibility не верифицирован.
**Estimated effort:** 2-3h execution + benchmark.
**Discovery completed:** 2026-05-04.

| Resource | Status |
|---|---|
| USB4 link evo1 ↔ evo2 (`thunderbolt0` 10.0.0.1/30 ↔ 10.0.0.2/30) | ✓ UP, 0.642 ms RTT, 0% loss |
| evo1 rpc-server binary `/data/llama-cpp/llama.cpp/build/bin/rpc-server` | ✓ present (196 KB, Vulkan-enabled with gfx1151 detected) |
| evo1 port 50053 (proposed worker) | ✓ free (no listener) |
| evo2 llama-server binary | ✓ present (P4.3-Q235 standalone attempt confirmed) |
| evo2 qwen3:235b GGUF blob | ✓ at `/data/ollama-models/blobs/sha256-791d5d11998e006548d6b58c31756562ea61446ebc7d19686608402a797ecc82` (133 GiB) |
| Existing pipelines | glm-master on evo1:8081 → evo2:50052 (untouched by this sprint) |

Combined CPU RAM: evo1 30 GiB visible (96/32 UMA) + evo2 93 GiB visible (32/96 UMA) = ~123 GiB cluster CPU. **Note:** evo1 only has 30 GiB CPU due to AI-heavy UMA (96 iGPU). For the worker node, `--n-gpu-layers` decides whether layers offload to iGPU (32/96 GiB cap) or stay on CPU (30 GiB cap).

**Critical implication:** evo1 worker can offload to iGPU 96 GiB if Vulkan path used; OR evo1 can be CPU-only with 30 GiB (insufficient for ~half the model). **Vulkan via worker is the only viable path** — but Vulkan+UMA reports false 152 GiB available (same OOM trap as standalone). Need testing.

## Phase A — evo1 RPC worker on :50053 (new systemd unit)

```bash
# 1. Create systemd unit (reuse llama-rpc-worker.service pattern from evo2)
ssh -t evo1 'sudo tee /etc/systemd/system/llama-rpc-worker-q235.service >/dev/null <<EOF
[Unit]
Description=llama.cpp RPC Worker for qwen3:235b (USB4 link 10.0.0.1:50053, Vulkan backend)
After=network-online.target systemd-networkd.service
Wants=network-online.target

[Service]
Type=simple
User=banxe
Group=banxe
WorkingDirectory=/data/llama-cpp/llama.cpp/build
Environment=HSA_OVERRIDE_GFX_VERSION=11.5.1
Environment=GGML_VK_VISIBLE_DEVICES=0
ExecStart=/data/llama-cpp/llama.cpp/build/bin/rpc-server --host 10.0.0.1 --port 50053 -d Vulkan0 --threads 16 --cache
Restart=always
RestartSec=10
TimeoutStartSec=60
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now llama-rpc-worker-q235.service && sleep 5 && systemctl is-active llama-rpc-worker-q235.service'
# Expect: active

# 2. Verify port from evo2
ssh evo2 'ss -tln 2>/dev/null; nc -zv 10.0.0.1 50053 2>&1'
# Expect: connection succeeded
```

## Phase B — evo2 master on :8082 with --rpc (replace failed standalone unit)

```bash
# 1. Stop the failed standalone unit (if still present)
ssh -t evo2 'sudo systemctl disable --now qwen3-235b-master.service 2>/dev/null; sudo rm -f /etc/systemd/system/qwen3-235b-master.service'

# 2. Create new RPC-enabled master unit
ssh -t evo2 'BLOB=/data/ollama-models/blobs/sha256-791d5d11998e006548d6b58c31756562ea61446ebc7d19686608402a797ecc82
sudo tee /etc/systemd/system/qwen3-235b-master.service >/dev/null <<EOF
[Unit]
Description=qwen3-235b-a22b RPC master (evo2 master + evo1:50053 worker, per ADR-018 P4.3-Q235)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=moriel-carmi
Group=moriel-carmi
WorkingDirectory=/data/llama-cpp/llama.cpp/build
ExecStart=/data/llama-cpp/llama.cpp/build/bin/llama-server \\
  --model $BLOB \\
  --rpc 10.0.0.1:50053 \\
  --n-gpu-layers 999 \\
  --ctx-size 8192 \\
  --threads 16 \\
  --metrics \\
  --port 8082 \\
  --host 0.0.0.0 \\
  --api-key sk-rpc-q235-2026
Environment=HSA_OVERRIDE_GFX_VERSION=11.5.1
Environment=GGML_VK_VISIBLE_DEVICES=0
Restart=always
RestartSec=15
TimeoutStartSec=900

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now qwen3-235b-master.service'
# WARNING: model load can take 5-10 min on first start (mmap 133 GiB across two nodes via RPC).

# 3. Poll health
ssh evo2 'until curl -s -m 5 http://127.0.0.1:8082/health 2>/dev/null | grep -q "ok"; do sleep 30; date "+%H:%M:%S still loading"; done; curl -s http://127.0.0.1:8082/health'
```

**Critical risk gate:** if master OOMs on either node:
- Lower `--n-gpu-layers` step-by-step (999 → 80 → 60 → 40) to keep more layers on CPU.
- If still OOM, MoE+RPC is incompatible; this sprint is BLOCKED → defer to llama.cpp upstream MoE-RPC support.
