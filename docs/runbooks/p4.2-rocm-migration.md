# Runbook: P4.2-ROCm — Ollama Vulkan → ROCm migration

**Sprint anchor:** ADR-018 §"Required sprints to reach 100%" item 4 (marked optional, +30-50% throughput).
**Goal:** flip Ollama backend from Vulkan to ROCm 6.3 on both EVO-X2 nodes for measurable throughput gain.
**Risk:** medium — Strix Halo gfx1151 ROCm support is recent (ROCm 6.3 first official release Dec 2024); regression to Vulkan is single env-var revert.
**Estimated effort:** 30 min execution + 30 min benchmark per node = ~2h total.
**Discovery completed:** 2026-05-04.

---

| Node | ROCm packages | gfx1151 detected | Ollama backend (current) | Ollama ROCm runner present |
|---|---|---|---|---|
| evo1 | ✓ ROCm 6.3.0 full stack (`/opt/rocm-6.3.0/`, hip-runtime-amd, hipblas, hipblaslt, libamdhip64.so.6, librocblas.so.4, librocsparse.so.1) | ✓ rocminfo: Marketing Name "AMD Radeon Graphics", Name `gfx1151`, 32 CUs | `vulkan` (override.conf: `OLLAMA_LLM_LIBRARY=vulkan`) | ✓ `/usr/local/lib/ollama/rocm` (Ollama 0.22.1 bundled) |

## Phase A — evo1 switch (low-risk path: pre-install ready, just env flip)

```bash
# 1. Pre-flight benchmark (Vulkan baseline)
ssh evo1 'ollama run llama3.3:70b "Reply only: ok" --verbose 2>&1 | tail -10' \
  > /tmp/evo1-vulkan-baseline.txt
# capture eval rate (tokens/s)

# 2. Edit override.conf — replace vulkan→rocm
ssh -t evo1 "sudo sed -i 's/OLLAMA_LLM_LIBRARY=vulkan/OLLAMA_LLM_LIBRARY=rocm/' \
  /etc/systemd/system/ollama.service.d/override.conf"
ssh evo1 'cat /etc/systemd/system/ollama.service.d/override.conf | grep LLM_LIBRARY'

# 3. Reload + restart ollama (drops in-flight requests; LiteLLM v2 LB falls back to evo2)
ssh -t evo1 'sudo systemctl daemon-reload && sudo systemctl restart ollama.service'
ssh evo1 'systemctl is-active ollama.service'                # expect active
ssh evo1 'sleep 5 && journalctl -u ollama -n 30 --no-pager | grep -iE "rocm|hip|gfx|library|backend|error" | tail -15'
# Expect log lines mentioning ROCm/gfx1151 detection, no errors.

# 4. Smoke test — load + inference
ssh evo1 'time ollama run llama3.3:70b "Reply only: ok" --verbose 2>&1 | tail -10' \
  > /tmp/evo1-rocm-smoke.txt
# Expect: same response, similar or higher eval rate.

# 5. Throughput benchmark (50-token completion, repeat 3 times)
ssh evo1 'for i in 1 2 3; do
  curl -s -m 60 http://127.0.0.1:11434/api/chat \
    -d "{\"model\":\"qwen3.5:35b\",\"messages\":[{\"role\":\"user\",\"content\":\"Count from 1 to 50 in one line\"}],\"stream\":false,\"options\":{\"num_predict\":80,\"temperature\":0}}" \
    | jq -r ".eval_count, .eval_duration" \
    | paste - - \
    | awk "{printf \"run-$i: %.2f tok/s\n\", \$1 / (\$2 / 1e9)}"
done' | tee /tmp/evo1-rocm-bench.txt
```

**Pass criteria for evo1:**
- `systemctl is-active ollama` = active
- journalctl shows ROCm backend selection, no fatal errors
- inference returns expected text
- eval rate ≥ Vulkan baseline (target: +20-50%)

**Rollback (if any failure):**
```bash
ssh -t evo1 "sudo sed -i 's/OLLAMA_LLM_LIBRARY=rocm/OLLAMA_LLM_LIBRARY=vulkan/' \
  /etc/systemd/system/ollama.service.d/override.conf"
ssh -t evo1 'sudo systemctl daemon-reload && sudo systemctl restart ollama.service'
```

## Phase B — evo2 ROCm install (heavier — needs apt install before flip)

```bash
# 1. Install ROCm 6.3 stack (mirrors evo1)
ssh -t evo2 'sudo apt update && sudo apt install -y \
  hip-runtime-amd hipblas hipblaslt hipcc \
  rocm-hip-runtime rocm-hip-libraries rocm-llvm-dev \
  librocblas-dev librocsparse-dev'
# ~500 MB download, ~1.5 GB on disk.

# 2. Verify install
ssh evo2 'rocminfo 2>&1 | grep -E "ROCk module|Marketing Name|gfx" | head -5'
# Expect: ROCk loaded, gfx1151 detected.

# 3. Same env flip as evo1
ssh -t evo2 "sudo sed -i 's/OLLAMA_LLM_LIBRARY=vulkan/OLLAMA_LLM_LIBRARY=rocm/' \
  /etc/systemd/system/ollama.service.d/override.conf"
# Note: also remove OLLAMA_VULKAN=1 (vestigial)
ssh -t evo2 "sudo sed -i '/OLLAMA_VULKAN=1/d' \
  /etc/systemd/system/ollama.service.d/override.conf"
ssh evo2 'cat /etc/systemd/system/ollama.service.d/override.conf'

# 4. Reload + restart + verify (same pattern as Phase A step 3-5)
ssh -t evo2 'sudo systemctl daemon-reload && sudo systemctl restart ollama.service'
ssh evo2 'systemctl is-active ollama.service'

# 5. llama-rpc-worker (uses Vulkan via -d Vulkan0 explicitly) — leave untouched.
#    glm-master on evo1 still works via this RPC worker; ROCm change of ollama doesn't touch llama.cpp.
```

**Pass criteria for evo2:**
- All Phase A criteria, plus
- llama-rpc-worker.service still active (glm-master pipeline intact)
- LiteLLM v2 22 routes still respond

## Operator gates (required pauses)

| Gate | Reason | Authorization |
|---|---|---|
| Phase A step 2 (sudo sed) | edit prod systemd unit override | sudo on evo1 |
| Phase A step 3 (sudo restart) | drops in-flight LiteLLM requests; ~15s outage on evo1 ollama | sudo + brief downtime |
| Phase B step 1 (apt install) | adds ~1.5 GB to evo2 /opt; touches package state | sudo + disk |
| Phase B step 3-4 (sudo sed + restart) | same as Phase A | sudo + brief downtime |

**Rollback** is single-line `sed` revert + restart on each node — fast and safe.

---

## Recommendation

Per CANON-9 best-answer: execute **Phase A first** (evo1 only — already has ROCm installed; just env flip). Benchmark. If positive AND no errors after 30 min observation → proceed Phase B (evo2 install + flip). If negative on evo1 → rollback, document, do NOT touch evo2.

Sequential phasing preserves cluster availability: при Phase A evo1 outage LiteLLM falls back to evo2 (still Vulkan); при Phase B evo2 outage falls back to evo1 (now ROCm). Only failure mode = both down simultaneously, prevented by sequential gates.
