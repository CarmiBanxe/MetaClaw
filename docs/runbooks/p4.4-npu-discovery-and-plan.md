# Runbook: P4.4-NPU — XDNA 2 NPU Enablement (Discovery + Implementation Plan)

**Sprint anchor:** ADR-018 §"Required sprints to reach 100%" item 3 (after P4.3-evo2 ✅ DONE, P4.3-Q235 DEFERRED).
**Goal:** Light up AMD XDNA 2 NPU on both EVO-X2 nodes for sub-10W small-model inference (Layer 3 of canonical 5-layer architecture).
**Risk:** HIGH — AMD Ryzen AI Linux SDK is experimental; Strix Halo (gfx1151) is brand-new silicon with sparse community examples.
**Estimated effort (full):** 4-6h focused session.
**Discovery completed:** 2026-05-04 (this document).

## Implementation plan (4-6h, dedicated session)

### Phase A — Toolchain install (~1h, both nodes)

```bash
# 1. Add AMD repo (if not already present)
ssh evo1 'amdgpu-install --list-usecase'  # confirm repo
# Sudo install — operator OPERATOR_RUN:
ssh -t evo1 'sudo apt update && sudo apt install -y xrt xrt-dev libamdxdna-dev'
ssh -t evo2 'sudo apt update && sudo apt install -y xrt xrt-dev libamdxdna-dev'

# 2. Verify XRT
ssh evo1 'xrt-smi examine'
# Expect: NPU device 0000:c7:00.1 listed, status "OK"
ssh evo2 'xrt-smi examine'
# Expect: NPU device 0000:c6:00.1 listed, status "OK"
```

**Risk gate:** If `xrt-smi` doesn't list the XDNA NPU, it's a userspace/kernel mismatch — try AMD's experimental package from https://repo.radeon.com/ryzen-ai/.

### Phase B — Python ONNX runtime with Ryzen AI EP (~1h, both nodes)

```bash
# Per AMD docs, install Vitis AI Execution Provider for ONNX Runtime
ssh evo1 'python3 -m venv ~/.venv/npu && source ~/.venv/npu/bin/activate && pip install onnxruntime-vitis-ai'
ssh evo1 'source ~/.venv/npu/bin/activate && python3 -c "import onnxruntime as ort; print(ort.get_available_providers())"'
# Expect: ['VitisAIExecutionProvider', 'CPUExecutionProvider']
```

**Fallback:** if `onnxruntime-vitis-ai` PyPI wheel isn't published for Linux/Strix Halo:
- Build from source: https://github.com/microsoft/onnxruntime#vitis-ai
- Use AMD's prebuilt wheel from https://ryzenai.docs.amd.com/

### Phase C — POC model (~1.5h, evo1 only)

Pick small classification model:
- **MobileNet v3 INT8** (5 MB, good for image classification benchmark)
- **BERT-tiny INT8** (17 MB, NLP relevance for KYC text matching)

```bash
# Download pre-quantized AMD model zoo example
wget https://huggingface.co/amd/mobilenetv3-int8/resolve/main/model.onnx -O ~/npu-poc/mobilenet.onnx
wget https://huggingface.co/amd/mobilenetv3-int8/resolve/main/vai_xclbin.xclbin -O ~/npu-poc/mobilenet.xclbin

# Run inference
python3 << 'PY'
import onnxruntime as ort
import numpy as np
sess = ort.InferenceSession(
    "/home/banxe/npu-poc/mobilenet.onnx",
    providers=[("VitisAIExecutionProvider", {"xclbin": "/home/banxe/npu-poc/mobilenet.xclbin"})],
)
x = np.random.rand(1, 3, 224, 224).astype(np.float32)
import time
t = time.perf_counter()
for _ in range(100):
    sess.run(None, {"input": x})
print(f"avg latency: {(time.perf_counter() - t) * 10:.2f} ms")
PY
```

**Pass criteria:** avg latency < 10 ms (vs ~30-80 ms on CPU), power draw < 10 W (measure via `sensors` / `radeontop`).

### Phase D — LiteLLM integration (~1h)

Add small-model NPU routes to `~/MetaClaw/litellm/litellm-config.v2.yaml`:

```yaml
# NPU classification route (ADR-018 Layer 3)
- model_name: classify-img
  litellm_params:
    model: openai/mobilenet-v3-npu
    api_base: http://192.168.0.72:8090/v1   # custom FastAPI wrapper around ort session
    api_key: os.environ/NPU_API_KEY
```

Requires writing a thin FastAPI wrapper (~50 lines) that exposes ort.InferenceSession via OpenAI-compatible /v1/* endpoints. Out of scope for v1 — phase C is enough to prove the silicon works; Phase D wires it later.

### Phase E — systemd unit + node_exporter metrics (~30 min)

Create `banxe-npu-server.service` on each node mirroring banxe-guardian-{factory,project} pattern. Add `/metrics` endpoint with NPU utilization counters via `xrt-smi --json`.

## Risks (HIGH)

| # | Risk | Mitigation |
|---|---|---|
| 1 | `onnxruntime-vitis-ai` PyPI wheel may not exist for Linux/Strix Halo | fallback: build from source (adds ~2h) OR use Ryzen AI Software prebuilt tarball |
| 2 | `xclbin` (binary kernel) availability — AMD Model Zoo may not have Strix Halo (gfx1151) variants | use AMD's `vai_q_onnx` quantizer to compile own xclbin from FP32 ONNX (adds ~1h) |
| 3 | Kernel driver `amdxdna` may need newer version than Ubuntu 24.04.4 ships | upgrade to HWE kernel 6.11+ (already on noble HWE), OR DKMS build from AMD source |
| 4 | NPU power management may interfere with iGPU UMA allocation | verify via `radeontop` + `xrt-smi examine` after first inference |
| 5 | Strix Halo NPU (XDNA 2) is brand-new silicon (Q4 2025 launch); community Linux examples sparse | rely on AMD Ryzen AI docs at https://ryzenai.docs.amd.com/ + AMD Discord #ryzen-ai-linux |
