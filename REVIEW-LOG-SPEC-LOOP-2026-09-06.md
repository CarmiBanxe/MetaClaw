## Поправка к итерации 3 (14:20Z) — четвёртый собственный ошибочный замер

Я записал «`.local` убран ✓», опираясь на `git ls-files`. Это **индекс, а не коммит**.

```
git show --name-only --format= 800209c05 → OPERATOR-BRIEF-S11-ADDENDUM-2026-09-06.local.md
git ls-tree -r HEAD --name-only        → он же
git status --porcelain                 → D <файл>, M .gitignore, M sandbox-manifest.json
```

Исправление исполнителя лежало в индексе незакоммиченным. Практическое следствие, которого
не было бы видно из ошибочного замера: удаление **отдельным коммитом поверх** оставляет файл
в истории ветки и уводит его в `main` при merge. Нужен amend самого `800209c05` — ветка не
запушена (37308 висит на старом `1bb38d4f8e63`), поэтому переписывания общей истории не
требуется.

Записано как и три предыдущих: ошибочный замер о надёжности метода говорит больше удачного.
Общий вывод по методу — **утверждение о содержимом коммита проверяется по коммиту**
(`git show`, `git ls-tree`), а не по индексу.
