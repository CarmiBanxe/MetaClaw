# L8 — фактическая диспетчеризация команд: внешняя проба

## Способ запуска

Отдельный экземпляр Claude Code в неинтерактивном режиме, **вне рабочих деревьев**, в пустом
каталоге `~/.claude/jobs/95502a54/tmp/l8probe`:

```
claude -p "/<команда>" --permission-mode plan --output-format stream-json --verbose
```

Конкурирующей исполнительной линии не создаёт: каталог пуст, запись в проектные деревья
отсутствует, режим `plan`.

**Версия пробы: 2.1.263** (бинарник с диска). Живые рабочие окна работают на **2.1.246 …
2.1.261** — результат относится к версии пробы и на них не переносится.

## Результат 1 — перечень команд, объявленный харнессом при инициализации

Из события `system/init` потока:

```
slash_commands (отфильтровано): ['spec', 'spec-review', 'spec-status', 'code-review']
```

**`review` и `status` в перечне отсутствуют** — переименование доехало, коллизия имён снята.
`code-review` присутствует как встроенная.

## Результат 2 — фактическое исполнение `/spec-status`

Вызов вернул содержательный отчёт **проектной инструкции**, а не встроенной команды состояния
приложения:

> `## /spec-status — отчёт` · «Состояние: каталог `specs/` пуст, спецификаций в проекте нет» ·
> таблица «Активные спецификации / В фазе SPEC / В фазе BUILD / В фазе REVIEW / CLEAN» ·
> «Следующий шаг: … вызов `/spec <name>`»

Встроенная `/status` печатает состояние приложения — модель, лимиты, каталог. Полученный ответ
структурирован по фазам петли, то есть исполнена команда приказа.

## Результат 3 — `/spec-review`

Команда принята и развёрнута: экземпляр начал работу (обращения к файловой системе в потоке).
Полный ответ не получен — прогон прерван таймаутом 100 с, поскольку команда выполняет
содержательный review. Перечень команд в `init` для этого вызова тот же.

## Результат 4 — контрольный `/review`: ПОЛУЧЕН

Повторный прогон с границей 280 с (прежние 100 с не хватало: команда делает содержательную
работу). `rc=0`, 24850 байт потока.

Перечень при `init`: `['spec', 'spec-review', 'spec-status', 'code-review']` — `review` в нём
**отсутствует**, но вызов сработал: ответ начался словами

> «**Ревью не выполнено — ревьюировать нечего. Findings: 0 (пустой список, не „чисто“).**
> … Рабочий каталог … это не репозиторий, а стенд пробы. Диффа под ревью не существует
> физически»

Это поведение **встроенной проверки кода**: она ищет дифф в репозитории. Проектная команда
искала бы спецификацию в `specs/` и печатала бы отчёт по фазам петли — как это сделала
`/spec-status`. **Псевдоним встроенной команды пользовательскую не запускает** — документированное
правило подтверждено фактическим вызовом, а не только отсутствием имени в перечне.

## Вызовы всех четырёх команд — состояние проверки

| Команда | Вызов | Результат |
|---|---|---|
| `/spec-status` | выполнен | **проектная инструкция** — отчёт по фазам петли |
| `/spec-review` | выполнен | принята и развёрнута; полный ответ прерван таймаутом |
| `/spec` | выполнен | **проектная инструкция** — «`/spec` вызван без аргумента задачи… писать спецификацию не из чего» |
| `/build` | **не завершён** | таймаут 200 с (`rc=124`); перезапущен с запасом 420 с |
| `/review` (контроль) | выполнен | **встроенная проверка кода** — ищет дифф репозитория |

Перечень харнесса при `init` во всех прогонах: `['build', 'spec', 'spec-review', 'spec-status',
'code-review']` — `review` и `status` отсутствуют, коллизия снята.

## Статус: PARTIAL

| Утверждение | Доказано |
|---|---|
| коллизия имён снята | **да** — `review`/`status` отсутствуют в перечне харнесса |
| `spec-status` исполняет проектную инструкцию | **да** — отчёт по фазам петли |
| `spec-review` принимается и разворачивается | **да** — по началу исполнения |
| `/review` уходит во встроенную проверку кода | **да** — ответ ищет дифф репозитория, а не спецификацию |

**Ограничение метода, не требования:** проба выполнена бинарником **2.1.263**; живые рабочие
окна работают на **2.1.246 … 2.1.261**, и запустить старую версию нечем — на диске лежит одна.
Результат относится к версии пробы. Это граница окружения, а не невыполненная часть требования:
предмет L8 — что команды вызывают предусмотренные режимы, и это показано фактическим вызовом.

**Прежнее заключение «требуется ввод человеком» отменено:** внешняя проба выполнима, выполнена
и завершена полностью.
