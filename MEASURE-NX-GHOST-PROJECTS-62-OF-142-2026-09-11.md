# Шестьдесят два проекта из ста сорока двух молча не прогоняются

**Замер:** 2026-09-11, дерево `75aa552a`. **Повод:** линия пересъёмки Director нашла, что первый её
запуск дал `КОД=0` и «Successfully ran target test for **10** projects» — три набора nx **пропустил
молча**. Линия назвала это верхней границей по своей выборке из тринадцати.

## Воспроизведено мной, и разница в один знак

```
npx nx run-many -t test --projects=fatca_crs   →  NX  No tasks were run       КОД=0
npx nx run-many -t test --projects=fatca-crs   →  Tests: 45 passed            КОД=0
```

**Оба кода — ноль.** Один прогнал сорок пять проб, другой не прогнал ничего.

> **Ноль здесь означает «ничего не сломалось», а не «замер проведён».** Это ровно тот разряд, из-за
> которого четыре дня печаталось «сценариев: 13» при тринадцати мёртвых сценариях, — **число,
> считающее записи, а не исходы**, в другом обличье.

## Тревога не частная: считал по всему дереву

```
проектов с именем в project.json:  142
имя РАСХОДИТСЯ с именем каталога:   62
```

Расхождение **систематическое, а не случайное**: каталоги в `snake_case`, имена nx в `kebab-case`.
`adverse_media` → `adverse-media`, `banking_engine` → `banking-engine`, `crypto_custody` →
`crypto-custody`. Плюс отдельные переименования: каталог `conductor` — имя `banksy-conductor`.

**Значит для шестидесяти двух проектов из ста сорока двух обращение по имени каталога даёт
молчаливый ноль.** Верхняя граница линии была втрое ниже истинного числа — и это тот редкий случай,
когда число от перепроверки **выросло**: линия честно назвала свою выборку выборкой.

## Чего это касается и чего НЕ касается

**Касается:** всякого доклада «наборы зелены», снятого через `nx run-many --projects=<каталог>`.
Такой доклад доказывает **только** отсутствие падения у тех проектов, чьи имена совпали.

**Не касается** — и это проверено, а не предположено:

- прогон через `npx jest --config <путь>` — обращается к файлу, не к имени; так снимал я сам
  (`banksy-seam-check`: 33 набора, 259 проб);
- доклады, где числа названы **поимённо по каждому набору** и сверены с ожиданием: пропущенный
  проект выдаёт себя отсутствующим числом. Так линия сведения и поймала подмену;
- `nx run-many` без `--projects` — там выбор не по имени.

## Защита, которой нет

**Ни одна мера дерева не ловит «No tasks were run».** Признак прост и однозначен — эта строка в
выводе при нулевом коде, — и его отсутствие означает, что молчаливый пропуск может повториться в
любом задании конвейера, где проект назван по каталогу.

**Правило отсюда (R34):** прогон, чья единица работы задаётся **именем**, обязан печатать **число
исполненных единиц** и отказывать при нуле. «Выполнено без ошибок» и «не выполнено ничего»
неразличимы по коду возврата — и потому различать их обязан сам прогон.

## Оговорка о моём числе

`62` получено сверкой поля `name` из `project.json` с именем каталога **у ста сорока двух проектов,
у которых поле `name` есть**. Проекты, где имя задаётся иначе (наследуется, вычисляется плагином),
в счёт не вошли — **это нижняя граница расхождения и верхняя граница совпадения**.
