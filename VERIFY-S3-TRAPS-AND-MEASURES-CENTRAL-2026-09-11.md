# Независимая проверка двух линий: три западни и мины мер

**Проверял:** центральный терминал — своим прогоном и **своими** подсадками, не отчётами линий.
**Дата:** 2026-09-11.

## Линия 1 — три западни `LocalEnforcement`

Ветка `agent/factory/director01/s3-traps`, коммит `d777cab5`.

### Числа и расхождение, которое я обязана была разобрать

```
мой прогон в worktree как есть:  272 пробы — 269 зелёных, 3 красных
тот же набор на дереве b87a9041: 258 проб — 258 зелёных, красных 0
```

Линия сообщила, что три красных «красны и на исходном снимке». **По букве это не так**, и я не
приняла формулировку на веру. Причина разобрана до конца:

```
● одновременное потребление › нет .../dist/banksy-mlro-boundary/src/durable-receipt.js:
  «гонку ничем не проверить. Цель test объявлена зависящей от build — отсутствие сборки
   есть неисправность конвейера, а не повод не проверять»
```

**Проба отказывает вслух вместо тихого пропуска** — образцовое поведение. После сборки
`tsc -p libraries/banksy-mlro-boundary/tsconfig.app.json`:

```
272 пробы — 272 зелёных, красных 0
```

**Работа чиста.** Формулировка линии была неточна («на исходном снимке» вместо «в свежем worktree
без сборки»); предмет назван ею верно.

### МОЯ канарейка на главную западню

Устройство, которое линия сделала, читается прямо:

```ts
const base = declared ?? ALL_RECEIPTS_REQUIRED;          // неизвестное действие → ВСЕ квитанции
requiresModel: base.requiresModel || d?.requiresModel === true,   // вызывающий может лишь УЖЕСТОЧИТЬ
```

Моя подсадка возвращает решение вызывающему (`d?.X ?? base.X`):

```
политика на месте : 272 пробы,  0 красных
решение у вызывающего: 272 пробы, 3 КРАСНЫХ — все три «S3-07 — обязательность задаёт
                                              серверная политика, а не поля запроса»
возврат           : 272 пробы,  0 красных
```

**Различает точно: краснеют ровно пробы названного предмета.** Западня `S3-07` закрыта.

### Названное линией незакрытым — принимаю

`new LocalEnforcement(` вне проб по-прежнему **0**: композиции нет, и звено остаётся `НЕ ЗОВЁТСЯ`.
Производственных `ReviewPort`/`BrokerPort` нет, потому `R14`/`A10` — происхождение модели из
доверенной конфигурации — сегодня **невыразимы, а значит и не измерены**. Линия назвала это сама.

**Отдельно отмечаю приём линии.** Ослепление записано `&& (false as boolean)`, а не `&& false`:
литеральный `false` метит тело недостижимым, сужение типов пропадает и ослепляется **сборка**, а не
страж. Линия поймала это собственным прогоном (238 проб вместо 272) и назвала отступление прямо.
**Я сегодня наступила на ту же грань и тем же способом её нашла.**

## Линия 2 — мина карантина и сиротские самопроверки

Ветка `agent/factory/director01/measure-fixes`, коммиты `f61f84f3`, `4f7392bf`.

```

      замер: «КАРАНТИН (…/device_fingerprint/PARITY-REPORT.md) — приговор не требуется»

      замер: строки освобождения БОЛЬШЕ НЕТ

```

**Выпущенная служба перестала получать карантинное освобождение.** Ровно то, ради чего работа.

Линия сверх требуемого показала `A4`: смена `policy/mode.yaml` с `sandbox` на `preprod` переводит
`emulated-sandbox` в `quarantined` **арифметикой**, без отзыва записи — как и требует решение 2.

### Числа не сдвинулись, и это половина успеха

```
обход мер          69 = 67 прошло · 0 отказало · 2 неверный вызов   — до и после одинаково
гейт карантина     Universe 99 / Released 0 / Quarantined 94        — БАЙТ В БАЙТ
замер долговечности  все приговоры прежние; единственная разница вывода —
                     добавленная строка «ИСТОЧНИК СОСТОЯНИЯ КАРАНТИНА: …»
```

**Правка предмета не есть правка результата** — при сегодняшнем `Released 0` и не должна была им
быть.

### Расхождение счёта, которое линия НЕ стала подгонять

Я называла «объявили самопроверку и не зовутся — **6**, убудет до 3». Линия своим признаком
получила **11 → 8** и **прежнюю арифметику воспроизвести не смогла**. Вместо подгонки под моё число
она назвала причину каждого остатка поимённо: пять мер печатают свои подсадки **обычным прогоном**
(и конвейер их зовёт — проверено живьём, 34 · 16 · 24 · 12 строк о подсадках), а `durability_survey`
задания в конвейере не имеет вовсе.

**Линия права, а моё число было занижено** — тем же устройством, что и прочие мои числа: узкий
признак. Требуемые три убыли; остаток без названной причины роняет меру.

**Это правильное поведение исполнителя:** не сходиться с числом заказчика, а назвать, почему оно
иное.
