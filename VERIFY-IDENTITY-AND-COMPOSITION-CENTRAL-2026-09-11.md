# Независимая проверка: источник личности и композиция `LocalEnforcement`

**Проверял:** центральный терминал своими прогонами и **своими** канарейками. **Дата:** 2026-09-11.

## Источник личности песочного уровня — `conductor-doors` · `72e95fee`

```
мой прогон: 30 наборов · 422 пробы · красных 0    (было 410)
```

### Устройство, проверенное чтением

Назначение выдаёт **256 бит из `randomBytes`**; носитель хранит **только `sha256`**. Удостоверения
в носителе нет, и потому **чтение носителя не равно назначению**. Соответствия «строка →
должность» **не существует ни одного** — единственное упоминание `sim://sandbox` во всём файле есть
комментарий, объясняющий его отсутствие.

### Моя канарейка

Ослепил сверку предъявленного (берётся первое назначение вместо поиска по отпечатку):

```
сверка на месте : 422 пробы,  0 красных
сверка ОСЛЕПЛЕНА: 422 пробы,  4 КРАСНЫХ
   FN-D-08 · R4/R5 · вызывающий не вправе назначить себе личность
   FN-D-08 · R6 · назначение, отзыв и разбор
   FN-D-08 · живая сборка: четыре двери оживают ОДНИМ источником
сверка возвращена: 422 пробы, 0 красных
```

418 прочих зелены. **Различает по предмету.**

*О моих же попытках:* первые две ослепления уронили сборку (одно било в другой `records.get` — путь
отзыва, — второе оставило неиспользуемую переменную). Оба записаны: это измерения компиляции, а не
стража, и они не в счёт.

### Находка линии, которую стоит выписать в правило

> «Первая редакция сверяла предъявленное **дважды**: поиском по отпечатку и `timingSafeEqual` над
> теми же отпечатками. **Ослепление поиска НЕ покраснило ни одной пробы** — вторая копия молча
> доделывала работу за первую.»

**Копии одного предиката прячут друг друга от канарейки.** Пока обе согласны, ослепление одной
ничего не меняет, и проба меряет не то, что называет. Копия убрана, сравнение одно, канарейка после
этого заговорила.

**Это новое правило, и оно общее:** непокрасневшая канарейка означает либо подмену предмета, либо
**дублирующий предикат**. Второго я прежде не встречала.

## Композиция `LocalEnforcement` — `s3-traps` · `bd9f9484`

```
построений `new LocalEnforcement(` вне проб:   дерево 0  →  ветка 1
   (второе совпадение grep — упоминание в шапке того же файла; линия различила это сама)
banksy-mlro-boundary:  272 → 292 · красных 0
banksy-seam-check:     230 → 232 · красных 0
```

**Звено «локальное принуждение» перестало быть построенным только в пробах.**

### Три производственных порта — и почему каждый устроен именно так

**Брокер** записывает намерение **в момент выдачи** квитанции и возвращает его **копией**: отдав
хранимый объект, брокер позволил бы предъявителю **переписать собственную запись брокера**. Умолчание
запрещающее — выдана без намерения, значит не связана ни с чем.

**Реестр ревью** берёт `emulated`, `independent`, `provenance`, `reviewerModel` **из доверенной
конфигурации**; заявление выдавшего о себе попадает в журнал `misdeclarations()` и **на решение не
влияет**. Это буквально `R16`. **Независимость считается по `family`, а не по строке `modelId`** —
буквально решение 2: «разные строки идентификаторов независимостью не являются».

**Надзор** читает, но **не потребляет**: потребление атомарно и идёт своим ходом; потребить здесь
значило бы сжечь годную квитанцию на запросе, который дальше по порядку всё равно откажет.

### Доказательство, что связывание держит ВЫДАВШИЙ, а не проба

Промежуточный помощник `связанный(broker, ENF)` **удалён**; в принуждение подаётся сам брокер.

```
шов 12: пакет с намерением `release_hold`, квитанция предъявлена под `payment.send`
        → MODEL_RECEIPT_FOR_OTHER_SUBJECT
шов 13: пакет без намерения → квитанция выдана, но bindingOf = null
        → MODEL_RECEIPT_NOT_ISSUED_BY_BROKER
К15:    ослеплена сама запись намерения В БРОКЕРЕ → шов 12 краснеет
```

**Если бы связывание держала проба, ослепление брокера ничего бы не изменило.** Канарейка красит
шесть проб, и линия объяснила почему: без записи выдавшего цепь «облако → принуждение» перестаёт
работать целиком. **Это измерение того, что запись держит, а не шум.**

## Незакрытое — принято как названное линиями

| | |
|---|---|
| `A8` сквозные сценарии | реестр не перезамерян; статус `НЕ ЗОВЁТСЯ` в нём может остаться прежним |
| носители принуждения непрочны | реестр ревью и хранилище квитанций не переживают перезапуск; CAS атомарен внутри процесса |
| **сборка есть функция, а не вызов** | `A7` закрыт **буквой**: построение вне проб есть, живого процесса, который его строит, — нет |
| независимость автора | берётся по `authorRuntimeId`, который называет **заявляющая сторона**; закрывается аттестацией автора, которой в реестре нет |
| `R17` | умеет назвать зависимость предметно, но три записи контура живут только в пробах — конфигурационного файла в дереве нет |
| `restore` и `hitl/decisions` | зовут ту же функцию личности, но пробы **живой сборки** есть только у рычага и копии |

**Обе работы приняты.**
