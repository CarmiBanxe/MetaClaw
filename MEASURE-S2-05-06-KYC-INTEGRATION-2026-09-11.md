**Снимок:** `b87a9041`. **Дата:** 2026-09-11.
**Основание:** решение 3 — ветвь A (порт и общие типы в библиотеку, реализация остаётся в службе);

## Порт: поверхность и потребители

`services/onboarding/kyc/src/kyc-provider-port.ts` — **девять исполняемых экспортов** плюс типы:

```
KYCTier · ProviderKYCStatus · ProviderLevelId · KYCSession · KYCResult · WebhookOutcome
KYCProviderError · InvalidSignature · UnknownUser · ProviderUnavailable
TierDowngradeBlocked · WebhookReplayDetected · KYCProviderPort · DeferredKYCProviderAdapter
```

**Потребителей вне своей службы — ноль.** Единственные упоминания в дереве:

```
services/onboarding/kyc/src/index.ts:2              export * from "./kyc-provider-port"
services/onboarding/kyc/src/kyc.characterization.spec.ts  — собственный набор службы
```

**Следствие для S2-05.** Перенос в библиотеку сегодня **не меняет ничего наблюдаемого**: переносить
нечего ломать и некому замечать. Это подготовка, и решение 3 прямо запрещает засчитывать её за
восемь функций.

## Что это уточняет в потолке 57

Потолок `49 → 57` остаётся верным **как потолок**: восемь достижимы без оператора, карантин их не
держит. Но это **не восемь готовых к засчитыванию** — это восемь **ненаписанных**, и расстояние до
них равно полной разработке по `specs/onboarding-kyc-orchestration.md`, а не переносу файла.

**Порядок, следующий из решения 3:**

```
S2-05 перенос порта  →  подготовка, НЕ закрывает ни одной функции
S2-06 восемь функций →  разработка + фактическая интеграция + проверки
```

Перепутать их местами значило бы объявить восемь закрытыми по появлению библиотеки — ровно то, что
решение 3 запрещает дословно.
